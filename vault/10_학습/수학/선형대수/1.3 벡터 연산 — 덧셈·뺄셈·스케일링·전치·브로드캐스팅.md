> 🎯 **핵심 (TL;DR)**
> - **덧셈** = 머리-꼬리(head-to-tail([hɛd tə teɪl], 헤드 투 테일, 헤드 투 테일)) 연결, 원소별 합. **교환법칙** 성립. **같은 차원에서만.** *(= 평행사변형의 대각선 — 같은 그림의 다른 이름)*
> - **뺄셈** = 원소별 차. 기하 = *두 머리를 잇는 선*(둘째 머리→첫째 머리) — 직교분해·회귀의 기초.
> - **스케일링(스칼라곱)** = 각 원소에 스칼라 곱, 길이만 조절. **음수 = 방향 반전이지만 같은 선상**(→ 선형 종속의 씨앗, [[1.8 벡터 확장 — 집합·선형결합·선형독립·부분공간·생성·기저|1.8]]).
> - **전치(transpose)** = 행↔열 뒤집기. `vᵀᵀ=v`. $X^{\mathsf{T}}X$ = 대칭 공분산(PCA의 뿌리).
> - ⚠️ **방향이 결과 차원을 바꾼다:** 열벡터+행벡터 → **브로드캐스팅**으로 (3,3) *행렬*. 스칼라-벡터 덧셈도 수학 불가·파이썬 허용.
> - **벡터 평균** = 다 더하고 `1/N` 곱. "데이터 조작 = 벡터 조작".
> - 🔑 **다섯 중 원시 연산은 둘뿐** — **합·상수배**만 벡터 공간 $(V,+,\cdot)$ 의 정의에 들어 있다. 뺄셈·평균은 *파생*, 전치는 *표기 도구*, 브로드캐스팅은 *구현 도구*. 이 둘에 닫혀 있음 = **선형성**, 이 둘을 한 번에 쓰면 = **선형 결합**([[1.8 벡터 확장 — 집합·선형결합·선형독립·부분공간·생성·기저|1.8]]).

> [!question] 🎯 필요성 사슬 (결핍 → 필요 → 발명)
> *출발 문제:* 데이터(벡터)를 실제로 *조작*하려면 — 합치고, 차이를 재고, 키우고, 축을 맞추고, 중심을 구해야 한다.
> 1. 벡터 하나로는 여러 데이터를 합칠 수 없음 → 결합 연산 필요 → **덧셈(머리-꼬리)**
> 2. 두 데이터가 얼마나·어느 쪽으로 다른가 → 차이 연산 필요 → **뺄셈(두 머리 잇는 선)**
> 3. 크기를 조절하고 싶음(평균의 1/N, 가중치) → 길이 조절 필요 → **스케일링(음수=반전)**
> 4. 내적·노름($v^{\mathsf{T}}v$)을 행렬곱으로 쓰려는데 행/열이 안 맞음 → 축 눕히기 필요 → **전치**
> 5. 모양 다른 배열을 루프 없이 연산 → 자동 확장 필요 → **브로드캐스팅**(단 방향 틀리면 행렬이 튀어나옴)
> **한 줄:** 결합(덧셈)→차이(뺄셈)→조절(스케일링)→정합(전치)→확장(브로드캐스팅) — "데이터 조작 = 벡터 조작". *이 연산들의 무한 조합이 만드는 공간(스팬)은 [[1.8 벡터 확장 — 집합·선형결합·선형독립·부분공간·생성·기저|1.8]]에서.*

> **① 벡터 생성 (예제 4-1~4-4)** — 리스트 `[3,2]`/`np.array`/3D/5D. 정의·차원·방향·도판(그림 4-1~4-3)은 [[1.1 벡터 — 정의·차원·방향|1.1]] 소관.
>
> **② §4.1.1 덧셈과 결합 (예제 4-5)** — 두 이동을 **머리-꼬리 연결**, 끝점이 결과.
> $$ \vec v+\vec w=\begin{bmatrix}3\\2\end{bmatrix}+\begin{bmatrix}2\\-1\end{bmatrix}=\begin{bmatrix}5\\1\end{bmatrix} $$
> - **교환 법칙(commutative([kəˈmjuːtətɪv], 커뮤터티브, 커뮤터티브)):** $\vec v+\vec w=\vec w+\vec v$ (그림 4-6). 실제 의미: 데이터 합산.
>
> **③ §4.1.2 스케일링 (예제 4-6)** — **스칼라**(하나의 값)를 각 원소에 곱해 길이 조절.
> $$ 2\vec v=\begin{bmatrix}6\\2\end{bmatrix},\quad 0.5\vec v=\begin{bmatrix}1.5\\0.5\end{bmatrix} $$
> - **크기만 변하고 방향은 그대로.** 음수 스칼라 = 방향 반전(그림 4-9)이지만 *같은 선상*. 데이터 의미: **평균** = 합산 후 `1/N` 스케일링.
>

> [!abstract] 📘 책 핵심 — [실전선대] §1.2 벡터 연산
> **① §1.2.1 덧셈/뺄셈** — 원소별, *같은 차원에서만* (ℝ([ɑːr], 알, 알)³+ℝ⁵ 불가).
> $$ \begin{bmatrix}4\\5\\6\end{bmatrix}+\begin{bmatrix}10\\20\\30\end{bmatrix}=\begin{bmatrix}14\\25\\36\end{bmatrix},\quad \begin{bmatrix}4\\5\\6\end{bmatrix}-\begin{bmatrix}10\\20\\30\end{bmatrix}=\begin{bmatrix}-6\\-15\\-24\end{bmatrix} $$
> - **방향이 중요(식 1-4):** 열벡터 + 행벡터는? → **브로드캐스팅**으로 *행렬*이 나온다.
>
> **② §1.2.2 덧셈/뺄셈의 기하** — 덧셈=머리-꼬리(그림 1-2 A). **뺄셈=두 머리를 잇는 선**(둘째 머리→첫째 머리, 그림 1-2 B). *직교벡터 분해·선형 최소제곱(회귀)의 기초.*
>
> **③ §1.2.3 스칼라-벡터 곱** — 각 원소에 스칼라 λ([ˈlæmdə], 램더, 람다) 곱. $\lambda=4,\ \lambda w=[36,16,4]^{\mathsf{T}}$. 방향 안 바뀌고 크기만(음수=180° 반전, 같은 선상 — 그림 1-3).
> - ⚠️ **λ 신분 지도 (첫 등장 — 전방 주의):** 이 책은 λ를 "아무 스칼라"의 범용 글자로 재사용한다. ① **계수·배율** — 여기 스케일링, [[1.8 벡터 확장 — 집합·선형결합·선형독립·부분공간·생성·기저|1.8]] 선형결합의 λᵢ, [[2.6 행렬 공간 — 열공간·행공간·영공간|2.6]] 열공간에선 전 실수를 훑는 **자유 변수**로 확장 ② **조율 상수** — [[2.1 행렬 연산 — 덧셈·뺄셈·이동·스칼라곱·아다마르곱|2.1]] 이동 $A+\lambda I$, *사람이 고르는 고정값* ③ **고윳값** — $Av=\lambda v$, *행렬이 정해주는 값* `(🔭 예고)`. 같은 글자, 세 신분 — 맥락으로 구분.
>

>
> **④ §1.2.4 스칼라-벡터 덧셈** — *수학적으론 불가*(별도 객체). 파이썬은 **브로드캐스팅**으로 각 원소에 더함: `2 + [3,6] = [5,8]`. **벡터 평균** = 덧셈 + 스칼라곱(1/N).
>
> **⑤ §1.2.5 전치(transpose)** — $m^{\mathsf{T}}_{i,j}=m_{j,i}$, 열벡터↔행벡터. **`vᵀᵀ=v`**. *데이터 행렬 $X^{\mathsf{T}}X$ = **대칭 공분산 행렬*** → PCA([piː siː eɪ], 피시에이, 피시에이)가 직교 회전인 이유.
>
> **⑥ §1.2.6 브로드캐스팅** — 현대 컴퓨터 선대만의 연산(전통 교과서엔 없음). 한 벡터를 다른 벡터의 각 원소로 반복 연산. 행+열 → 행렬. 효율·간결(k-평균 등).
> - **책 예제** — $[1,2,3]^{\mathsf{T}}$(열)과 $[10,20]$(행)의 패턴을 모은 덧셈:
> $$\begin{bmatrix}1&1\end{bmatrix}+\begin{bmatrix}10&20\end{bmatrix},\ \begin{bmatrix}2&2\end{bmatrix}+\begin{bmatrix}10&20\end{bmatrix},\ \begin{bmatrix}3&3\end{bmatrix}+\begin{bmatrix}10&20\end{bmatrix}$$
> 이 세 줄을 **하나의 브로드캐스팅 식**으로 간결화하면 $(3,1)+(1,2)\to(3,2)$:
> ```python
> v = np.array([[1,2,3]]).T   # 열벡터 (3,1)
> w = np.array([[10,20]])     # 행벡터 (1,2)
> v + w
> >>> array([[11, 21],
>            [12, 22],
>            [13, 23]])
> ```

*원문 그림 3 — 두 벡터 $\vec{a}$와 $\vec{b}$의 합인 $\vec{a}+\vec{b}$. 출처: 공돌이의 수학정리노트(Angelo's Math Notes), 「벡터의 기본 연산(상수배, 덧셈)」, CC BY-NC 4.0 — [원문](https://angeloyeo.github.io/2020/09/07/basic_vector_operation.html).*

**작도와 성분 계산이 왜 같은 답을 주는가** — 그림 3의 값 $\vec a=[3,1]^{\mathsf{T}}$, $\vec b=[1,3]^{\mathsf{T}}$ 로 직접 확인:

- **두 경로가 같은 점에 도착한다.** $\vec b$ 를 $\vec a$ 의 머리로 평행이동하면 끝점이 $(3,1)+(1,3)=(4,4)$, 거꾸로 $\vec a$ 를 $\vec b$ 의 머리로 옮겨도 $(1,3)+(3,1)=(4,4)$. **이 "같은 점"이 곧 교환법칙**이며, 성분별 덧셈이 실수 덧셈의 교환법칙을 그대로 물려받은 결과다. 그림 3의 빨간 대각선 끝점 $(4,4)$ 와도 일치.
- **닫힌 도형이 평행사변형인 근거:** 변 $B\to A{+}B$ 는 $(4,4)-(1,3)=(3,1)=\vec a$, 변 $A\to A{+}B$ 는 $(4,4)-(3,1)=(1,3)=\vec b$ — 마주보는 변이 *같은 벡터*(평행 + 등길이)이므로 평행사변형 확정.
- ⚠️ **이 그림 하나로 일반화하지 말 것.** 그림 3은 $\lVert\vec a\rVert=\lVert\vec b\rVert=\sqrt{10}$ 인 **마름모**라 대각선이 두 벡터 사이 각을 정확히 이등분한다. 일반 평행사변형에서는 이등분하지 **않는다** — "합은 항상 두 벡터의 가운데 방향"은 이 그림에서 잘못 굳는 암기다.
- 🧭 **"꼬리를 옮겨 그리는 건 반칙 아닌가?"** 수학의 벡터는 시점이 원점인데(→ [[1.1 벡터 — 정의·차원·방향|1.1]]의 **기준 위치**(standard position)) 머리-꼬리·평행사변형은 화살표를 평행이동해 그린다. 모순이 아니다 — **실선** $\vec a$·$\vec b$·$\vec a+\vec b$ 는 전부 원점에서 출발하고 옮겨 그린 **점선은 작도 보조선**이다. 평행이동은 *시각화 편의*일 뿐, 벡터의 정체는 **성분**이다. 픽셀 계측·전체 검증 → [[벡터의 기본 연산 — 상수배·벡터 간의 합 (공돌이의 수학정리노트 정리)|공돌이 원문 정리 §검증 2 · 정밀성 갭 3]].

>
> | | 스칼라 `2` | 1×1 행렬 `[[2]]` |
> |---|---|---|
> | 정체 | 원시 타입(순수 크기/배율) | 2차원 배열 **객체**(공간 변환기) |
> | `ndim` / `shape` | `ndim=0` | `shape=(1,1)` |
> | 연산 | **브로드캐스팅**(모든 원소에 침투) | **행렬 곱**(규격 맞물림: 앞 가로1=뒤 세로1) |
>
> ```python
> col = np.array([[3],[1]])         # 2×1
> col * 2                           # 브로드캐스팅 → [[6],[2]]
> np.dot(col, np.array([[2]]))      # 행렬곱 (2×1)·(1×1) → [[6],[2]]  (같은 결과)
> np.ndim(2), np.array([[2]]).shape # 0 , (1,1)  ← 정체는 다름
> ```
> - **왜 수학은 둘을 엄격히 구분?** *행렬은 공간을 변환하는 **함수***. `[2]`는 "1차원 공간을 2배 스케일하는 변환기", 스칼라 `2`는 공간 의미 없는 순수 숫자([[3D 변환 행렬 — 동차좌표·회전·투영 (선형대수 응용)|3D 변환]] · [[1.1 벡터 — 정의·차원·방향|1.1]]의 '수학 차원 ≠ ndim' 연장).

### 🔑 왜 하필 '합'과 '상수배'인가 — 둘만 원시 연산, 나머지는 파생·도구

위 🎯 **필요성 사슬**은 다섯 연산을 *필요가 생긴 순서*로 늘어놨다. 같은 다섯을 이번엔 **신분**으로 갈라 보면 층이 하나 더 드러난다. 외부 글(공돌이의 수학정리노트)은 아예 **"벡터의 기본 연산은 총 두 가지 — 상수배, 그리고 벡터 간의 합"** 이라고 못 박고 시작한다.

| 연산 | 신분 | 근거 |
|---|---|---|
| **벡터 간의 합** $x,y\in V\Rightarrow x+y\in V$ | **원시**(primitive([ˈprɪmɪtɪv], 프리머티브, 프리미티브)) | 벡터 공간 $(V,+,\cdot)$ 정의에 들어 있는 `+` 그 자체 |
| **상수배** $x\in V,\ k\in\mathbb{R}\Rightarrow kx\in V$ | **원시** | 같은 정의의 `·` 그 자체 |
| 뺄셈 | 파생 | $\vec v-\vec w=\vec v+(-1)\vec w$ — 상수배 1회 + 합 1회 |
| 벡터 평균 | 파생 | 합 $N{-}1$ 회 + 상수배($1/N$) 1회 |
| 전치 | **표기 도구** | 성분을 바꾸지 않는다. 행렬곱 차원을 맞추려 *적는 방식*만 눕힌 것 |
| 브로드캐스팅 | **구현 도구** | 수학 정의가 아니라 계산 편의(§1.2.4·1.2.6 — 전통 교과서엔 없음) |

- **왜 이 둘만 특권을 갖나 — 선형성 때문이다.** 이 두 연산이 잘 정의되는(=닫혀 있는) 대상은 **선형성**(linearity([lɪniˈærɪti], 리니애리티, 리니어리티))을 만족하고, 선형인 것은 수학적으로 다루기 쉽다. 그래서 선형대수는 "선형인 것들을 찾아 연구"한다 — 화살표로 그릴 수 없는 함수·행렬까지 벡터로 취급할 수 있는 근거가 이것(→ [[1.1 벡터 — 정의·차원·방향|1.1]]의 정의 층위 ③ '벡터 공간의 원소').
- ⚠️ **닫힘 두 개 = 벡터 공간이 아니다.** 닫힘은 **필요조건일 뿐**이고 공리가 8개 더 있다(단위원 $1\cdot x=x$ 등 — 이게 빠진 반례가 실제로 만들어진다). 주인은 [[1.5 벡터 공리 — 덧셈·음수·역원|1.5]], 반례는 [[벡터의 기본 연산 — 상수배·벡터 간의 합 (공돌이의 수학정리노트 정리)|공돌이 원문 정리 §정밀성 갭 1]].

**둘을 한 번에 쓰면 그게 선형 결합 — 그리고 그게 데이터 변형의 최소 도구다.**
말이 어려워서 그렇지 선형 결합은 *상수배와 합을 한 번에 조합한 것*일 뿐이다. 5명의 국어 점수 $k$ 와 영어 점수 $e$ 로 두 과목 평균을 내는 계산이 이미 그 실물이다:

$$avg=\tfrac{1}{2}k+\tfrac{1}{2}e=\tfrac{1}{2}\begin{bmatrix}100\\70\\30\\45\\80\end{bmatrix}+\tfrac{1}{2}\begin{bmatrix}83\\50\\25\\30\\60\end{bmatrix}=\begin{bmatrix}91.5\\60\\27.5\\37.5\\70\end{bmatrix}$$

각 성분이 두 과목의 산술평균과 일치한다(직접 확인: $(100{+}83)/2=91.5$ … $(80{+}60)/2=70$). "평균 내기"라는 데이터 변형이 **상수배 한 번 + 합 한 번**으로 끝난다.

- **계수가 손잡이다.** $(\tfrac12,\tfrac12)$ 를 $(0.7,\,0.3)$ 으로 바꾸면 가중평균, 아무 실수나 놓으면 $c_1\vec v_1+c_2\vec v_2$ — **선형 결합**. 위 🪂 '벡터 평균 = 데이터 평균'이 말한 것의 일반형이다. PCA·SVD·선형회귀·ICA가 전부 *데이터를 벡터로 보고 상수배와 합으로 주무르는* 이 관점 위에 있다.
- 🌉 **1.8로 가는 다리.** $c_1,c_2$ 를 **모든 실수**로 훑었을 때 도달하는 벡터들의 집합이 **생성(span)**, 그게 어디까지 덮는지가 **선형 독립·기저** 문제다 → 주인은 [[1.8 벡터 확장 — 집합·선형결합·선형독립·부분공간·생성·기저|1.8 벡터 확장]](여기선 정식 정의를 반복하지 않는다). ⚠️ "선형결합 → 공간 전체"는 **선형독립일 때만** 참이다 — $[1,0]^{\mathsf{T}},[2,0]^{\mathsf{T}}$ 로는 $c_1,c_2$ 를 아무리 바꿔도 $y=0$ 인 직선 하나만 덮는다.
- 🎓 **AI 렌즈로 넘어가는 지점.** 위 🌉 '스케일링·음수반전 = 선형 변환의 특수 경우'가 말한 신경망 $Wx+b$ 의 **왜**가 여기다 — 선형층이 하는 일이 결국 입력 벡터들의 선형 결합이다.

## 🧩 코드 실습 (필수 §4.1 + 실전 §1.2)
> 🎯 목표: 덧셈(교환법칙)·뺄셈·스케일링(음수 반전)·열+행=행렬·전치(vᵀᵀ=v)·평균을 코드로.
> 코드: `~/LOCAL/notebooks-mirror/ai-practice/01_linear_algebra/md4_vector_ops.py` · `la1_2_ops.py`

> [!tip] 🧭 매핑 템플릿 — [수학] → [책 1D] → [내 2D]   `#규칙`
> 열벡터 $v=\begin{bmatrix}3\\2\end{bmatrix}$ 를:
> - **책(1D shortcut):** `np.array([3,2])` → `(2,)` *(.T 먹통)*
> - **내 표기(2D 명시):** `np.array([[3],[2]])` → `(2,1)` *(수식 1:1)* — 규칙 출처 [[T04 NumPy 벡터 내부 — shape·strides·열벡터 (N,1)|T04]]

```python
import numpy as np
# 덧셈 (예제 4-5) — 교환법칙 (열벡터 (N,1) 명시)
v = np.array([[3], [2]]); w = np.array([[2], [-1]])
print((v + w).ravel(), np.array_equal(v+w, w+v))      # [5 1] True
# 스케일링 (예제 4-6) — 음수=방향반전(같은 선상)
a = np.array([[3], [1]])
print((2.0*a).ravel(), (0.5*a).ravel(), (-1*a).ravel())  # [6. 2.] [1.5 0.5] [-3 -1]
# 뺄셈 (실전 §1.2.1)
p, q = np.array([4,5,6]), np.array([10,20,30])
print(p - q)                                          # [-6 -15 -24]
# 방향 다르면 행렬! (브로드캐스팅)
col = np.array([[4,5,6]]).T; row = np.array([[10,20,30]])
print((col + row).shape)                              # (3,3)
# 전치 왕복 / 스칼라-벡터 덧셈(broadcasting) / 평균
print(np.array_equal(row.T.T, row))                   # True (vᵀᵀ=v)
print(2 + np.array([3,6]))                            # [5 8]
print((np.array([2,8]) + np.array([4,2])) * (1/2))    # [3. 5.] 평균
```

관찰 포인트:
- **같은 차원만 덧셈/뺄셈** — 다르면 `ValueError`, *방향*이 다르면 브로드캐스팅 **행렬**.
- **`vᵀᵀ=v`** 왕복. 데이터행렬엔 `XᵀX`로 공분산.
- **열벡터는 `(N,1)` 명시** — 1D `(2,)`는 `.T` 먹통([[T04 NumPy 벡터 내부 — shape·strides·열벡터 (N,1)|T04]]).

## 🆕 새 용어 정리
| 용어 | 한 줄 정의 |
|---|---|
| **벡터 덧셈** | 머리-꼬리 결합(원소별 합); 교환법칙 `v+w=w+v`; 같은 차원만 |
| **벡터 뺄셈** | 원소별 차; 기하=두 머리를 잇는 선(직교분해·회귀 기초) |
| **스케일링 / 스칼라** | 스칼라(한 값) 곱으로 길이 조절; 음수=방향 반전(같은 선상) |
| **전치** (Transpose, vᵀ) | 행↔열 뒤집기; `vᵀᵀ=v`; `XᵀX`=공분산(대칭) |
| **브로드캐스팅** | 작은 배열을 전체에 퍼뜨려 연산(행+열→행렬); 컴퓨터 선대 전용 |
| **스칼라-벡터 덧셈** | 수학 불가, 파이썬은 broadcasting([ˈbrɔːdkæstɪŋ], 브로드캐스팅, 브로드캐스팅)으로 허용 |
| **벡터 평균** | 다 더하고 1/N 곱(=데이터 평균) |
| **영벡터 / 자명한 해** | 모든 원소 0 / 0으로 푸는 명백한 해(보통 제외) |
| 🆕 **평행사변형 작도** (parallelogram) | 두 벡터 합의 기하 표현 — 머리-꼬리를 두 방향으로 한 번씩 그린 것; **대각선이 합** |
| 🆕 **원시 연산 / 파생 연산** | 벡터 공간 정의에 든 연산(합·상수배) vs 그 둘로 조립되는 연산(뺄셈·평균) |
| 🆕 **선형성** (linearity) | 합·상수배가 잘 정의되는(닫힌) 성질 — 선형대수가 다루는 대상의 자격 요건 |

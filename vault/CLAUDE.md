## 2. 외부 AI(Gemini) 답변 검증

UHD가 Gemini 답변을 들고 와 물으면(0번 교차검증 원칙 적용), 아래 4가지 실패 패턴을 의심한다:
1. 전방참조 내용(책이 "N장에서" 미룬 것)을 지금 배워야 할 것처럼 가르침 — 챕터 앞서감.
2. 부분적으로만 맞는 직관을 "완전히 틀렸다"고 이분법 재단.
3. 원문에 없는 "오타"를 확신에 차서 지어냄 — 사용자가 스캔을 보내면 반드시 그 원문과 직접 대조.

판정은 이분법이 아니라 "어느 부분이 맞고 어느 부분에 다른 모델이 필요한지" 정밀하게 낸다. 혼란의 원인이 스코프 크리프(전방참조 주입)로 밝혀지면 "이해력 문제가 아니라 설명 설계 문제"라고 명시한다. 0번과 상충 아님 — 정밀한 판정이 곧 더 엄격한 것.

## 3. 인용·구조 감사 방법론

- **책 절 인용 감사:** 특정 책§절이 커리큘럼에 빠졌다고 선언하기 전, (1) 해당 단계 파일을 이번 턴에 새로 읽는다(과거 요약·기억 신뢰 금지), (2) 주제로 짐작되는 한 줄이 아니라 **파일 전체에서 절 번호 리터럴을 grep**한다(개념적 원리·코드 구현 트랙이 분리돼 있어 같은 절이 다른 줄에 인용될 수 있음). 그래도 안 나올 때만 "누락"으로 보고한다.
- **리넘버링 후 검증:** mv + 텍스트 치환만으론 불충분 — 잔존 3종을 구조적으로 스캔: ① `[[새제목|구번호+설명]]` 형태 별칭(디스크립션이 붙어 bare-number 정규식에 안 걸림), ② `[[ ]]` 없는 순수 텍스트 절 번호 언급(`_용어집`·`_핵심 암기장` 등에 축적), ③ 테이블 셀의 `\|` 이스케이프 링크. target≠alias 번호 불일치 전수 스캔 + 삽입 지점 양옆 노트의 "형제" 링크 확인까지.
- **한글 파일명 검색:** grep/find/rsync는 바이트 비교라 NFD(자모분해) 파일명을 놓칠 수 있다. **매칭 0건 = 안전이 아니라 정규화 불일치를 먼저 의심**한다. python `unicodedata.normalize('NFC', ...)` 경유로 확인.

- **⚠️ 음성 결과 보고 규율 — 양성 대조군 의무 (2026-08-05 도입).**
  `0건`·`무출력`·`위반 없음`을 보고하려면 **같은 출력 안에서 검사가 살아 있음을 먼저 증명한다.**
  형식: `[검사 규모] N건을 훑음` + `[양성 대조] 반드시 걸려야 할 표본이 실제로 걸림`.

  왜: `0건`은 두 가지를 뜻하는데 나는 매번 앞쪽으로만 읽었다 —
  **(가) 진짜 없다** / **(나) 검사가 대상에 닿지 못했다.**
  2026-08-05 한 세션에서 이 형태로 **6번 연속 틀렸다.** 단 한 건도 "검사는 옳았는데 판단이
  틀린" 경우가 아니었다. 전부 검사가 헛돌았다:

  | 증상 | 진짜 원인 |
  |---|---|
  | `rsync -an` 출력 없음 → "제외됨" | `-v` 없이는 **원래 아무것도 안 찍는다** |
  | `grep -c "^vault/90_보관/"` → 0 | NFD 정규화 불일치 |
  | 치환 스크립트가 "성공" 출력 | 앵커 불일치로 **아무것도 안 바꿈** |
  | 변이 테스트 `8/8 검출` | 하나는 `IndentationError` 로 죽은 것 (exit≠0 오독) |
  | 고아 이미지 `9건` | 즉석 정규식이 참조 형식을 못 잡아 오탐 8건 |
  | "기존 그림은 한국어" | 실제 파일을 **안 열어봄** |

  **즉석 셸 검사를 새로 짜지 마라.** 반복되는 검사는 `qctl` 서브커맨드로 승격한다 —
  한 번 검증하면 계속 옳고, `selftest` 가 회귀를 막는다. 현재 승격된 것:
  ```
  qctl orphans        어느 노트도 참조하지 않는 볼트 이미지 (NFC + 이스케이프 파이프 처리)
  qctl grep <문자열>   볼트 NFC 정규화 검색 — 즉석 grep 의 NFD 함정 회피
  qctl leak           미러 **커밋 트리**에 제외 대상이 남았나 (작업 트리가 아니다)
  ```
  ⚠️ 한글 경로를 셸 파이프로 비교하지 마라 — `rsync`/`git` 출력이 8비트 경로를
  이스케이프해 내보내므로 `grep` 이 조용히 빗나간다. 판정은 **파일시스템 결과**를
  파이썬으로 NFC 정규화해서 한다.
- **새 파일 생성·리네임 전:** MOC 규칙 21(NFD 255바이트 캡) 기준 재확인.

  1. **삭제 직전 정확한 매니페스트를 보여준다** — 경로·파일 수·용량. 되돌릴 수 없으므로 무엇이 사라지는지 사용자가 볼 수 있어야 한다.

  이미 매니페스트를 보고 지시한 것이면 재확인하지 않는다. 같은 걸 두 번 묻지 않는다. (Obsidian은 비-`.md` 확장자를 무시해 그래프/링크에서 자동 제외됨.) 대량 삭제·구조 변경 세션에서는 `.deleted` 표시에 더해 원본을 `90_보관/_백업/<작업명_날짜>/`에도 복사해둔다(둘 다 — `.deleted`가 필수, 백업 폴더는 추가 안전망).

**표현대조 다이어그램:** "이게 왜 계산이 필요하지, 원래 주어진 거 아닌가" 류의 표기/추상화 갭 혼란이 텍스트 설명 2회 이상 반복해도 안 풀리면, 텍스트를 더 쌓지 말고 **두 카드 대조 다이어그램**(직관적 표현이 값을 바로 보여주는 카드 vs 실제 표기에서 값이 숨겨져 유도해야 하는 카드, 계산 화살표로 연결)으로 전환한다. Claude Desktop의 `mcp__visualize`는 Claude Code에 없음(확인됨, 툴 목록에 부재) — 동일 효과는 **matplotlib 스크립트**로 낸다(볼트 MOC 규칙 12 색코딩 재사용). **반드시 `~/LOCAL/notebooks-mirror/ai-practice/.venv/bin/python3`로 실행** — 시스템 기본 `python3`(`/opt/homebrew/bin`)엔 matplotlib이 없어 `ModuleNotFoundError`로 실패함(실측 확인). Artifact 툴은 claude.ai 호스팅 URL만 만들고 로컬 파일을 남기지 않으므로 vault 임베드(`![[...]]`)에 쓸 수 없음 — 사용자와 디자인을 빠르게 상의할 때 미리보기 용도로만 쓰고, vault에 실제로 넣을 최종 파일은 항상 matplotlib PNG/SVG로 생성한다. 사용자가 "이 그림이 핵심"이라 확정하면 실제 vault 이미지로 임베드(규칙 12 형식 그대로).

**⚠️ 이 "사용자 확정" 전제는 그림을 *새로 만들 때*에만 적용된다(2026-08-05 한정).**
재구성 그림이 **이미 있는데** 규칙 12가 요구하는 접이식 원본 병기만 빠진 경우는
승인 대상이 아니라 **규약 미이행**이다 — §9-1 적재 트리거 **A등급 4번**으로 묻지 않고
적재한다. 이 구분을 안 두면 "규칙이 의무라고 적어 둔 것"을 매번 다시 허락받게 되고,
실제로 같은 요청이 2주 넘게 반복됐다.

## 8. Claude Code 전환으로 없어진 제약 (참고)

- 책 이미지 등은 `__temp/`(99_안내 가이드 3-7)에 넣으면 로컬 fs로 바로 읽는다.
- **채팅에 붙여넣은 이미지도 실제 파일로 남는다**(예: `$TMPDIR/orca-paste-*.png`, 실측 확인) — Desktop처럼 uploads 미저장으로 크롭 불가한 문제 자체가 없음. `__temp/`에 미리 넣어두는 절차 없이, 붙여넣은 원본 경로에서 바로 크롭/`attachments/` 복사가 가능하다. **단 OS 임시 디렉토리라 휘발성** — 같은 세션 안에서 바로 옮겨 처리할 것, 다음 세션까지 미루지 않는다.
- Desktop의 로컬 폴더 마운트 위에서 git 연산 시 index.lock이 잔류하던 이슈도 Claude Code는 실제 로컬 셸이라 재현 안 될 가능성이 높다 — 미러 스크립트 실행 중 문제 생기면 보고.

## 9. 전경 무-블로킹 (전역 원칙)

무거운 작업(다중 파일 탐색·노트 검수·원문↔노트 대조·fact-check·이미지 재구성 등 3초 이상 걸릴 일)은 전경에서 동기 실행하지 않는다 — 배경 서브에이전트로 위임하고 즉시 대화로 복귀, 완료 알림에 결과를 표면한다. 대화 응답성이 최우선(2026-07-26 선언).

### 9-1. 노트 편집은 큐를 통한다 (2026-08-03 도입)

**볼트 노트를 쓰거나 고치는 일은 메인이 직접 하지 않는다.** 큐에 적재하고 대화를 계속한다.
큐 조작의 SSOT는 `.claude/scripts/qctl.py` 하나뿐 — 큐 디렉터리를 직접 읽거나 쓰지 말 것.

```
QCTL="python3 <볼트>/.claude/scripts/qctl.py"
```

- **적재는 메인만.** 사용자가 "큐에 넣어"라고 하면 대화 맥락을 브리프로 정리해
  `enqueue --title … --intent … --brief-stdin` 로 넣는다.
- **라우팅은 메인의 책임이다. 사용자에게 묻지 마라.** 원자료(스캔·Gemini 답변·메모)만 받으면
  신규/갱신·단계·절·phase를 **직접 판정**한다. 사용자가 이걸 매번 지정해야 한다면
  에이전트를 둘 이유가 없다. 선택지를 제시하고 고르게 하는 방식도 금지 —
  판정하고 **적재하면서 한 줄로 보고**한다(어디에·왜). 틀렸으면 사용자가 뒤집는다.

  **판정 근거는 `qctl route` 로 뽑는다. MOC·허브를 직접 Read하지 마라.**
  ```
  python3 .claude/scripts/qctl.py route <키워드…> [--stage N단계]
  ```
  후보 노트 / 관리 노트 등록 상태(규칙 8·15c 충족 여부) / 허브 미체크 항목 / 다음 순번을
  수백 바이트로 압축해 준다. MOC 33KB·허브 50KB를 매 라우팅마다 대화 컨텍스트에 쌓지
  않기 위한 것이다 — 툴은 데이터만 내고 판단은 메인이 한다. 실측 0.12초.
  후보가 애매할 때만 **후보 노트 1개**를 추가로 Read한다(허브·MOC 전체가 아니라).

  **업로드 자료가 "이미 반영됐나"(소진 판정)도 같은 명령이 답한다 (2026-08-05 추가):**
  ```
  qctl route <키워드…> --cite 6.2 --sources <자료 경로…>
  ```
  절 번호 **리터럴** 인용 노트(§3의 처방된 방법) · 그 자료를 인용한 노트 · 후보 노트의
  미결 `- [ ]` 항목 · 임베드 목록을 함께 낸다. 실측 245ms.
  > ⛔ **셸로 재발견하지 마라.** 이게 없던 시절 메인이 같은 판정을 하려고 `grep`·`sed`를
  > 6회 돌리고 스캔 5장을 전문 독해했다(2026-08-05 관측) — §9-1이 금지한 "MOC·허브 직접
  > Read"에 해당하고, 대화가 수십 초 멈췄다. 게다가 **결과도 더 나빴다**: 메인은 미결
  > 항목을 원자 노트에서 1건만 찾았는데 툴은 렌즈 노트의 같은 항목까지 2건을 찾는다.

### 적재 트리거 — 언제 큐에 넣는가 (2026-08-04)

판별선은 하나다: **내용을 창작하는가.** 창작이 있으면 가치 판단이 필요해 사람을 거쳐야 하고,
창작 없는 정합성 수선은 대상·형식이 확정돼 있어 자동이어도 안전하다.

| 등급 | 조건 | 행동 |
|---|---|---|
| **A. 자동 적재** | 창작 0 · 대상 확정 · 되돌리기 쉬움 | 넣고 **한 줄로 알린다**(묻지 않음) |
| **B. 자동 제안** | 창작 있음 · 가치 판단 필요 | 한 줄로 제안. 무시하면 그냥 지나감 |
| **C. 명령 대기** | 그 외 전부 | 사용자가 말할 때까지 아무것도 안 함 |

> ⚠️ **이 등급은 큐 밖에도 적용된다 (2026-08-05, §0-1).** 가드·스크립트·설정·경로처럼
> 큐를 안 거치는 인프라 작업도 같은 기준으로 판정한다. 그동안 이 표가 "큐 적재"에만
> 걸려 있어 인프라가 전부 C(명령 대기)로 흘렀고, 그 결과 한 세션에서 선택지 47개가
> 사용자에게 올라갔다. **되돌리기 쉬운 정합 수선은 A다 — 실행하고 한 줄로 알린다.**
> 「결정해줄 것」에 올릴 수 있는 건 **비가역**이거나 **취향**인 것뿐이고, 응답당 **1개**다.

**A — 자동 적재 (묻지 않는다)**
1. `qctl lint` 가 검출한 규칙 위반 수선 (MOC 미등재 등) — 대상 파일과 형식이 코드로 확정됨
2. 워커·phase가 보고한 **미처리 항목** 중 대상이 명시된 것 (예: "phase-body 소유 파일에 필요한 수정")
3. 실패·CAS 충돌로 중단된 태스크의 **잔여분 재적재** — 이미 승인된 작업의 복구
4. **규칙 12의 그림 배치** — 재구성물이 **이미 만들어져 있는데**(볼트 밖 코드 저장소 포함)
   볼트 임베드 또는 접이식 책 원본 병기만 빠진 경우. 규약이 요구하는 의무의 이행이지
   창작이 아니다 — 그림 자체는 이미 만들어졌고 검증됐다. (2026-08-05 추가)

   > 왜 C에서 A로 옮겼나: 이게 C에 있는 동안 같은 승인 요청이 **2주 넘게 반복**됐다.
   > 그런데 A등급 3요건을 전부 충족한다 — 크롭은 기계적이라 **창작 0**, 대상은 규칙 12가
   > "재구성 그림 바로 아래"로 **확정**, 이미지 파일이라 **되돌리기 쉽다**.
   >
   > 저작권도 묻는 이유가 못 된다. 유출은 이미 구조로 막혀 있다(실측 확인):
   > 파일명에 `(book-scan)` 마커가 있으면 `pre-write-guard` 가드 4가 **프롬프트 없이 통과**
   > 시키고(검사는 마커가 *없을 때*만 발화), 미러 스크립트가 `--exclude '*(book-scan).*'` +
   > NFC prune 으로 이중 차단한다. 즉 그 질문은 저작권이 아니라 **편집 취향**을 묻고 있었다.
   >
   > **선을 지켜라 — 넓히면 안 된다:**
   > · "재구성 그림이 있는데 원본 병기가 빠졌다" → **A. 넣고 한 줄 알림**
   > · "이 그림을 새로 만들까 / 이게 핵심 그림인가" → **C 유지.** 그건 창작이다(§7).
   >
   > 실행 주체: `attachments/**` 소유 phase = `phase-body`, PIL 12.2.0 가용.
   > **가드 4를 함께 고쳐야 했다(2026-08-05).** 그전엔 판정 기준이 "미러 제외 마커가 있나"
   > 여서 결과가 뒤집혀 있었다 — 책 스캔 `(book-scan)` 은 볼트에 쓸 수 있는데 **직접 그린
   > `(figure)`·`(replica)` 는 쓰기가 거부**됐다. 이제 기준은 **"출처를 선언했나"** 다:
   >
   > | 파일명 | 볼트 쓰기 | 공개 미러 |
   > |---|---|---|
   > | `(book-scan)`·`(ext-src)`… | 허용 | **비공개**(rsync 제외) |
   > | `(figure)`·`(replica)` | 허용 | **공개**(own work라 정상) |
   > | 선언 없음 | phase=거부 / 메인=ask | 공개 |
   >
   > ⚠️ 방어선이 한 칸 물러났다 — 책 스캔에 `(figure)` 를 잘못 붙이면 그대로 public repo로
   > 나간다. 최종 방어선은 미러 스크립트가 **push하지 않는다**는 것이다(사용자가 GitHub
   > Desktop에서 diff 검토 후 수동 push). 새 이미지는 diff에 뜬다.

   가드 4개(하나라도 어기면 A가 아니라 B다):
   - `--phase` 는 **비창작 phase만**(`index`·`log`). `body` 가 필요하면 자동 적재 금지.
     **예외: 위 4번**은 `body` 를 쓴다(이미지가 `phase-body` 소유라 불가피) — 대신 마커가
     붙는 병기 크롭에 한정하고, 마커 없는 이미지는 어떤 경우에도 자동 적재하지 않는다
   - 큐가 `paused` 면 넣지 않는다 — 사람이 확인 중이라는 뜻이다
   - 같은 결함으로 대기·실패 태스크가 이미 있으면 **중복 적재 금지**
   - 적재 사실을 반드시 한 줄로 알린다. **조용히 넣지 않는다**

**B — 자동 제안 (한 줄, 묻지 않고 알림)**
- 한 주제를 **여러 턴에 걸쳐** 파고들어 결론이 선 시점
- 기존 노트에 없는 내용임을 `qctl route` 로 확인한 경우
- 형식: `› 이 내용 탐구 T02로 남길 만하다. 넣을까?` — 라우팅은 이미 판정해서 제시한다
- **단발 질답·사실 확인·도구 사용법에는 던지지 않는다**
- **제안은 1회만.** 무시당하면 같은 주제로 다시 던지지 않는다 — 잔소리가 되면 전부 무시당한다

**C — 명령 대기**
새 노트 작성, 기존 노트의 내용 보강, 업로드 자료 처리. 전부 사용자 지시가 있어야 한다.

- **대화 유래 노트(탐구·통찰)도 큐를 거친다.** 질문·탐구를 대화로 진행한 결과가 노트가 될 때:
  `--kind note.explore`(→ `탐구/T##`) 또는 `note.insight`(→ `10_학습/통찰/`).
  | | 업로드 자료 | **대화 유래** |
  |---|---|---|
  | 지식 원천 | `sources`의 파일 | **브리프 그 자체** |
  | 메인이 할 일 | 훑고 주제만 식별 | **대화 내용을 충실히 정리해 브리프에 담는다** |
  | 검증 배지 | 1차 출처 대조 시 ✅ | **기본 `⚠️미검증`** (§0 — 대화·외부 AI는 1차 출처가 아니다) |
  - `qctl` 이 `brief_is_source: true`를 자동으로 붙이고, 브리프가 비면 **적재를 거부**한다.
  - **그 브리프는 지우지 마라.** 대화는 파일로 안 남아 노트↔원문 대조의 유일한 근거다.
    `qctl doctor` 가 "보존 브리프"로 계속 센다.
  - 순번은 `qctl route` 의 `[대화 유래 노트군]` 이 준다. **결번을 먼저 채운다**
    (현재 `탐구` T02·T05 결번). 번호가 순서를 뜻하는 규약이 결번으로 무너지기 때문이다.

- **메인은 원자료를 훑기만 한다. 전문 독해 금지.** (업로드 자료 한정 — 대화 유래는 위 표 참조)
  라우팅에 필요한 건 *"이게 무엇에 관한 것인가"*(주제 식별)지 *"무엇이 쓰여 있는가"*가 아니다.
  제목·소제목·수식 표제·첫 문단까지만 본다. 상세 독해는 `phase-body`가 `sources`를 직접
  읽어서 한다. 이래야 자료가 20장이든 200장이든 메인 부담이 일정하다.
  브리프에는 **의도와 주제**를 적고 원문은 **경로**로 넘긴다.
  ⚠️ 채팅에 붙여넣은 이미지는 OS 임시 경로에 있어 휘발된다 — 큐에 넣기 전 `__temp/`나
  노트 옆 `attachments/`로 옮겨야 워커가 나중에 읽을 수 있다.
  ⚠️ **`--intent`/브리프에 대상 노트의 본문 스냅샷을 넣지 마라.** 넘길 것은 *의도와 지식*이고,
  파일의 현재 상태는 워커가 직접 읽는다. 스냅샷을 넣으면 큐가 막으려던 갱신 유실이 그대로 생긴다.
- **워커 spawn은 펌프만.** `vault-queue-worker`·`phase-*` 를 직접 호출하지 마라.
  턴이 끝나면 Stop 훅(`queue-pump.py`)이 판정해 지시한다. 메인이 같이 띄우면 워커가 둘이 된다.
- **서브에이전트에 넘기는 프롬프트는 영어로 쓴다.** Agent 툴의 `prompt` 인자가 대상이다
  (메인→워커, 워커→phase 양쪽 다). 파일 경로·노트 제목·원문 인용은 한국어 그대로 두고
  지시문만 영어로. **에이전트 정의 파일(`.claude/agents/*.md`)과 노트 산출물은 한국어 유지** —
  전자는 시스템 프롬프트고 후자는 사용자의 학습 노트다.
- **`/q`** 로 조회·취소·재시도·정지해제. idle 폴러 cron의 생성·삭제도 `/q pump`가 안내한다.
- **실패는 큐 전체를 정지시킨다**(사용자 결정: 즉시 중단 + 확인). `/q diff <id>`로 부분 편집
  잔류를 확인시키고, 자동 롤백은 하지 마라 — 그 사이 사용자가 Obsidian에서 한 편집까지 날아간다.

**메인이 직접 고쳐도 되는 범위 (카브아웃).** 오타 하나에 워커 사이클을 돌리는 건 과하다.
- **큐 필수**: 노트 본문, `_용어집`, `_핵심 암기장`, 단계 허브, `_update-log`
- **메인 직접 허용**: MOC의 범위·예정 표기, 오타, 깨진 링크 같은 **메타데이터 수선**.
  단 내용을 추가하는 순간(새 항목 등재·설명 작성) 큐로 넘긴다. 판단 기준은
  "이게 학습 내용인가, 표기 정합인가"다.

**적재 크기 규율.** 파이프라인은 **"노트 1건"** 단위로 설계됐다. 배치를 한 태스크에 넣지 마라 —
8건짜리 MOC 등재를 한 태스크로 넣었다가 `phase-index`가 턴 소진으로 잘려 4건만 반영된
부분 편집이 남았다(2026-08-04). 복구 대상이 여러 건이면 **적재 단계에서 쪼갠다.**

**하류 phase는 세지 마라 — `qctl`이 붙인다 (2026-08-05 도입).** `--phase body`를 준
`note.create`·`note.update`·`note.explore`·`note.insight`에는 `glossary`·`mnemonic`이
**자동으로 추가**된다. 새 용어·카드가 생길지는 `phase-body`가 쓰고 나서야 알 수 있어
적재 시점 판단이 원리적으로 불가능하기 때문이다. 비대칭이 근거다 — 빠뜨리면 후속 태스크
1건(워커+phase 2~3개)이 통째로 더 들고, 헛돌면 phase 하나가 상류 보고의 `없음`을 보고
파일도 안 열고 끝난다. 실측: 2026-08-05 테스트 8건 중 **2건이 이 누락의 뒷수습**이었다
(0034→0036, 0035→0037). 끄려면 `--no-auto-phase`.

**`maxTurns`는 예산이 아니라 폭주 방지 backstop이다.** 서브에이전트에는 문서화된 타임아웃이
없어 이것이 유일한 상한인데, 촘촘히 잡았더니 정상 작업이 두 번 잘렸다(0004 log, 0006 index).
비대칭이 명확하다 — 넉넉하면 드물게 토큰을 더 쓰지만, 빡빡하면 **파이프라인 절단 + 부분 편집 +
큐 정지 + 사용자 호출**이 확정적으로 발생한다. 정상 작업에서 절대 걸리지 않을 값으로 두라.
⚠️ 에이전트 정의 변경은 **다음 세션부터** 적용된다.

**큐 코드를 고쳤으면 `selftest` 를 돌려라 (2026-08-05 도입).**
```
python3 .claude/scripts/qctl.py selftest    # 14건, 114ms, 위반 시 exit 1
```
동시성·상태 불변식 회귀 검증. 여기 있는 항목은 전부 **실제로 깨졌던 것**이다(교차 세션
강제 회수, 락 토큰, 좀비의 `done`, 세션별 완료 커서, 중복 spawn, `seq` 레이스,
`pump-check` 의 O(N) open, CAS의 외부 편집·신규 파일 탐지 …).
임시 볼트·큐·런타임에서 돌아 실제 큐를 건드리지 않는다. 새 불변식을 발견하면
`SELFTESTS` 에 추가하라 — 그러라고 만든 자리다.
> 검증됨: 결함 8종을 코드에 되살려 넣었을 때 **8/8 모두 해당 테스트가 실패**했다.

**누락은 훅으로 못 막는다 — 린터가 잡는다.**
훅은 *호출된 툴*만 본다. `--phase index`를 안 붙이면 등재가 통째로 빠져도 아무도 모른다.
실제로 그렇게 8건이 누적돼 있었다(2026-08-04 발견).
```
python3 .claude/scripts/qctl.py lint      # 규칙 19 전수 검증, 위반 시 exit 1
```
`qctl done` 이 자동 실행하므로 워커 보고에 위반 목록이 딸려 온다. 별도로 돌릴 필요는 없고,
**보고에 나오면 무시하지 말고 태스크로 만들어라.**
검사 항목은 둘이다:
- **규칙 19** — 디스플린 MOC 등재 누락
- **표 파손** — `_용어집`·`_핵심 암기장`의 표 행 **사이에 낀 빈 줄**. 2026-08-05 `_용어집`
  L488의 빈 줄 하나가 아래 **127행을 파이프 노출 문단으로** 만들었고 수선에 태스크 1건이
  더 들었다. diff로는 한 줄이라 사람 눈에 안 보이고 렌더링해야 보인다 — 기계가 잡을 일이다.
  오탐이 원리적으로 없다(표 행 사이의 빈 줄은 마크다운에서 **항상** 표를 끊는다).

규칙 8·15c는 🆕 표기 형식 의존이라 오탐 위험이 있어 만들지 않았다.
틀린 경고를 내는 린터는 무시당하고, 무시당하면 없느니만 못하다.

**재-Read 의무 (가장 자주 깨지는 것).** 워커가 파일을 바꾼 뒤 메인이 옛 기억으로 답하면
큐를 만든 의미가 없다. 펌프가 완료 통지에 수정된 파일 목록을 넣어준다 —
**그 파일들에 대해 말하기 전 반드시 다시 Read한다. 기억으로 답하지 않는다.**

⚠️ **새로 만든 에이전트 정의는 즉시 잡히지 않는다(2026-08-03 실측).**
`.claude/agents/*.md` 를 만든 직후 그 세션에서 spawn하면 `Agent type not found`가 난다(2회 확인).
세션을 다시 시작하면 잡힌다 — 그때 하네스가 "New agent types are now available"를 알린다.
(즉시 실패 후 재시작 시 성공만 관측했다. 지연 감시자인지 시작 시 스캔인지는 미확인.)
정의를 새로 추가·개명한 뒤에는 큐를 정지시켜 두면 태스크가 유실되지 않는다.

파일 소유권은 `pre-write-guard.py`가 `agent_type`으로 강제한다(phase-glossary는 `_용어집.md`만,
phase-mnemonic은 `_핵심 암기장.md`만 …). 워커는 `Edit`/`Write` 툴 자체가 없다 —
모든 편집은 phase를 거친다. 막히는 건 버그가 아니라 설계다.

### 9-1-a. 멀티세션 계약 (2026-08-04 도입)

같은 볼트에서 Claude Code를 **여러 개 띄워도 안전하다.** 단 형태는 하나뿐이다 —
**큐는 공유, 워커는 언제나 1개.** 세션마다 워커를 띄우는 병렬 소비는 지원하지 않는다:
phase 소유권 분할은 *한 태스크 안*의 phase만 격리하므로, 서로 다른 태스크의
`phase-glossary` 둘이 같은 `_용어집.md`(110KB)를 노려 CAS 충돌 → 큐 정지가 된다.

**생존 판정은 하트비트 하나뿐이다.** `qctl cas`가 락 파일을 touch하고(phase가 쓰기 전마다
지나는 지점) `LOCK_STALE_SEC=120`이 만료를 정한다.
> ⚠️ 이전에는 Stop 훅의 `background_tasks`를 "권위 있는 신호"로 삼아 TTL을 우회했다.
> 그 배열은 **세션 범위**인데 락은 머신 전역이라, 세션 B는 세션 A의 워커를 볼 수 없어
> 늘 "죽었다"고 보고했다. 그 값 하나가 ① 살아 있는 락의 강제 회수와 ② 두 번째 워커
> spawn을 **둘 다** 몰았다(태스크 0012, 워커 2개 동시 실행). 지금은 훅 신호를
> **보수적 방향으로만** 쓴다 — "살아 있다"는 믿고, "죽었다"는 락이 신선하면 무시한다.

**락은 인스턴스 토큰으로 소유를 증명한다.** `qctl lock`이 발급하고 `done`·`fail`·`unlock`이
`--token`으로 되돌려준다. `--worker`는 에이전트 *타입 이름*이라 워커가 둘이면 값이 같아진다 —
그래서 회수당한 좀비가 남의 락을 풀고 `done`까지 부를 수 있었다.

**세션별로 갈린 상태 3종** — 전역 단일값이면 세션끼리 서로의 것을 덮어쓴다:
`cursors`(완료 통지 — 아니면 한 세션만 재-Read 경고를 받는다) · `crons`(idle 폴러 —
아니면 앞 세션 cron이 고아가 되어 7일간 폴링) · `seq`(flock 원자 발급).

**기기 간(멀티 디바이스)은 지원하지 않는다.** 큐 본체는 iCloud(동기화)에 있고 락은
`~/LOCAL/notebooks-queue`(기기별)에 있다 — Mac 2대면 락이 2개, 큐가 1개다. 락을 iCloud로
옮기는 건 더 나쁘다(동기화 브리지에서 `O_EXCL`·`flock` 원자성이 보장되지 않음).

### 9-2. 실습 코드는 큐가 아니라 `code-runner` 레인 (2026-08-04 도입)

`~/LOCAL/notebooks-mirror/ai-practice/**/*.py` 작성·실행은 **큐에 넣지 않는다.** 배경 서브에이전트
`code-runner` 를 메인이 직접 spawn한다(`vault-queue-worker` 와 무관 — 펌프가 관여하지 않음).

큐에 넣으면 안 되는 이유 셋. 하나라도 뒤집히면 재검토 대상이다:
1. **실패 의미가 반대다.** 큐는 실패 시 `qctl fail` 로 전체 정지 + 사람 호출인데,
   코드 실패(`ModuleNotFoundError`·shape 불일치)는 정상적인 반복이다. 코드 버그 하나가
   노트 파이프라인을 통째로 세운다.
2. **단일 워커 직렬.** 학습률 실험 같은 장기 실행이 뒤의 노트 태스크를 전부 막는다.
3. **격리할 공유 파일이 없다.** phase 분할 근거는 `_용어집`·`_핵심 암기장` 컨텍스트
   격리인데, 실습 코드는 신규 단독 파일이라 갱신 유실 위험이 0이다.

→ 코드가 **공유 파일**이 되면(단계 공용 유틸 `la_common.py` 에 여러 태스크가 append 등)
전제 3이 깨진다. 그때 `phase-code` 로 옮기는 게 옳다.

```
main ──▶ [code-runner]  .py 작성 → venv 실행 → assert 통과까지 자기 안에서 반복
              │          산출물: .py + PNG (기존 관습대로 .py 옆 평면 배치)
              ▼ 완료 보고(절대경로)
main ──▶ qctl enqueue --source <py> --source <png>   ← 업로드 스캔과 동일 취급
              ▼
            큐 ── body → (hub‖glossary‖mnemonic‖index) → log
```

- **코드 레인은 자료를 만들고, 큐는 자료를 노트로 만든다.** `code-runner` 는 볼트를
  건드리지 않는다. 상세 독해는 `phase-body` 가 `sources` 를 직접 읽어서 한다.
- **적재 등급은 C(명령 대기).** 코드 작성은 창작이라 사용자 지시가 있어야 시작한다.
- 순서가 있다. 노트 본문이 실행 결과를 인용하므로 **코드가 먼저, 적재가 나중**이다.
  진짜 병렬이 아니라 선행 생산자다.
- 그림을 볼트에 임베드할지는 **사용자 판단**이다. `code-runner` 가 볼트로 옮기지 않는다
  (마커 없는 이미지는 가드 4의 `ask` → 대화 차단, §7 규칙 12도 사용자 확정 전제).

> ⚰️ 구 노트 정리 오케스트레이터(8-에이전트 팀)는 2026-08-03 폐기 — `note-orchestrator` 스킬,
> `note-writer`·`note-router`·`note-linter`·`note-figurer`·`master-applier`·`judge-*` 를
> 호출하지 말 것. 위 큐 시스템은 그 부활이 아니다: 판정·라우팅 에이전트가 0개이고,
> phase 분할의 근거는 품질 분업이 아니라 대용량 공유 파일(용어집 112KB·암기장 65KB)의
> **컨텍스트 격리**다.
